Six signs of life

An organism,
not a script.

Each property is a mechanism in the organism contract — implemented, bounded, and inspectable. Not metaphors.

waits

Suspends on an external event — an approval, a mailbox message — and resumes under a new process, even in the other runtime. Acknowledged completed work is reused; uncertain writes stay blocked.

remembers

Durable slots, a content-addressed store, and semantic recall are language primitives. A program's memory persists across its lives — not a database you wire up.

decides

Model judgment is a declared effect: a typed cell with explicit context, an output contract, and a budget. Everything around it is pure dataflow.

reproduces

spawn admits a manifest emitted as ordinary data and runs it under the parent's bounds. A program can author its own successor.

evolves

A foundry measures candidate programs on declared cases and the host selects. Receipts keep the lineage of every proposal, measurement, and promotion.

leaves fossils

Every run produces a canonical receipt that replays bit-for-bit — verifiable without the model, the original store, or credentials.

The habitat

The computer
organisms live on.

ALGAL is also a machine. Programs run inside a habitat — store, registries, executors — under bounds the host controls.

Two runtimes, one contract. The native Rust kernel and the TypeScript reference execute the same manifest — and a saved run can suspend in one runtime and resume in the other, on a shared local store.

Models are peripherals, not the machine. An executor is admitted by the host like a device is attached to a computer — the organism declares what judgment it needs; it never mints the authority to get it.

The fossil record

leaves a fossil.

A receipt is the fossil record of an execution: content-addressed, canonical, replayable. Inspect a life after it ends.

Walk the evidence on the tour

  1. 01

    Verify

    Replay a run offline. Recorded effects are fixed; orchestration is recomputed bit-for-bit — no model, store, or credentials.

    algal verify receipt.json
  2. 02

    Diff

    Compare two executions: which cells diverged, and what each attempt cost.

    algal diff a.json b.json
  3. 03

    Diagnose

    Map a recorded failure back to the source expression that produced it.

    algal diagnose receipt.json

Replay checks execution consistency. It does not establish that a model answer is true or attest that a provider performed an operation.

Reproduction and selection

Programs propose.
The habitat selects.

An organism can emit a new manifest as data. spawn admits and runs it under the parent's budgets — generated programs are values, never code. Foundries and the civilization loop measure candidates on declared cases and promote winners.

  1. 01 / proposeCandidate artifacts

    Model-produced plans or manifests

  2. 02 / admitTyped, bounded programs

    Host compilation and checks

  3. 03 / measureEvaluation evidence

    Declared cases and work limits

  4. 04 / selectRetain or promote

    Host policy and recorded lineage

In one local on-device run (not published as replayable evidence): with Apple Intelligence as the designer, an on-device ~3B model proposed plans, a host function compiled them into checked manifests, and candidates passed their cases and promoted — a civilization epoch that never left the machine.

algal civ --live --apple --dir .algal/civ   # an on-device epoch
algal civ-verify --dir .algal/civ           # replay + audit it offline

Civilization workflows · Habitats and self-reproduction · Watch an organism propose a child on the tour

Proposal is not promotion. An organism cannot rewrite the runtime, mint authority, or select itself — the host owns admission and selection. The lifecycle above is conceptual; it is not a recorded winning run or a promise that a candidate improves.

Choose the right boundary

Life has limits.
Start bounded.

ALGAL fits local review queues, checked coding episodes, reusable judgment pipelines, and inspectable evidence. A single unstructured prompt may need less machinery. Existing durable workflow engines may already meet your recovery needs.

This is an application VM prerelease. Packages are unsigned and unnotarized. Hosts still own tool permissions, external-effect reconciliation, storage operations, and any required OS isolation. Multi-tenant service operation, distributed custody, and global quotas are unfinished.

Receipts check execution consistency, not factual truth or provider attestation. The adoption guide explains these boundaries before you connect a real system.
