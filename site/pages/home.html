Who it is for

For agents that wait on people,
restarts, and reviews.

Durable execution for agent work: the run outlives the process that started it, and the record outlives the run.

Teams with a person in the loop

Release reviews, change requests, drafts that someone signs off. The program puts its proposal in a mailbox and waits. The process goes away until the answer arrives.

Applications that embed agents

Your host decides which tools, models, and budgets a program gets, and inspects the program before it runs. A program cannot widen its own permissions.

Builders who want programs to improve

A program proposes a better version of itself. Your host evaluates candidates on your cases and adopts the winner, with its history kept.

The idea

A program is a value your system
can read, write, and keep.

An ALGAL program is typed data: a graph of steps, model calls, and tools with a content-derived identity. Readable source lowers to the same program, so a person, a macro, or a model can write one, and the host checks it the same way.

quote.lisp
01 / Write it as an S-expression
(program quote ((order json)) json
  (with-total subtotal
    (* (get order quantity) (get order unit_price))
    (record subtotal subtotal
            shipping (if (>= subtotal 50) 0 5)
            total (+ subtotal (if (>= subtotal 50) 0 5)))))

The macro expansion is printed and hashed.
Generated code stays inspectable, and the program digest matches the readable source exactly.

02 / Compose it
(program gross ((order json)) json
  (let gross (* (get order price) (get order quantity))
    (let tax (* gross 0.08)
      (record gross gross tax tax total (+ gross tax)))))

Immutable bindings, bounded fuel, no hidden effects.
Syntax never grants permissions. Waits, tools, and limits are declared in the program.

Once a procedure works, it keeps its digest, its record, and its place in every larger program that calls it. Read the language guide.

What it does

{{HEADING_HOME_PROCESS}}

A program pauses at an approval, the process exits, and the same program continues later on another machine from its recorded prefix. Finished work is never repeated.

waits

Wait for an approval or a message on a mailbox the host granted. The process exits; the checkpoint holds the place.

resumes

Continue in a new process, on a new machine, from the recorded prefix. A write with an unknown outcome stays blocked until it is reconciled.

decides

Give each model call its own context, expected answer shape, and budget. Everything around it is deterministic logic.

replays

Every model call and tool result is recorded. Replay a run and check it offline, without a model, a store, or credentials.

reproduces

A program proposes another program. The host checks it before running it inside the parent's limits.

evolves

Evaluate candidate programs on your cases and adopt the ones that win. Their scores and lineage are kept.

Compare

If you run Temporal, Restate,
Inngest, or LangGraph.

ALGAL shares their vocabulary: durable execution, workflows, checkpoints, replay, human-in-the-loop approval. The difference is that the workflow is data a host can inspect, hash, and run, not code in your process.

  • Temporalkeeps workflow history in its service; ALGAL writes each run to a receipt that verifies offline
  • Restatejournals handlers inside a server; ALGAL needs no server between invocations
  • Inngestcheckpoints functions on a cloud that bills per step; ALGAL runs from a local binary with no meter
  • LangGraphbuilds agents as code in your process; ALGAL's programs are typed data a VM runs
  • All comparisonsincluding DSPy and BAML
