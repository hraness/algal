Programs that grow.
More from every model.

ALGAL is two things. It is an agent harness where organisms are typed, replayable workflow graphs that can spawn and evolve into a civilization. And it is a way to squeeze more juice out of LLMs — cheap or frontier — by putting deterministic cells in charge of structure and using models only where judgment is needed.

A living agent harness

Organisms are data: hashable, transportable, evolvable. They can propose and spawn children, and a host can promote them into a civilization. It is not just a workflow — it is a self-reproducing ecosystem with a content-addressed fossil record.

Squeeze more juice from LLMs

Give small or large models narrower problems, the evidence they need, deterministic checks, and explicit escalation. Measure the result on your workload: more calls are not automatically better. Hosted, coding-agent, and on-device adapters belong behind the same bounded effect boundary. The sharpest trick is to ask the model for the smallest sufficient decision — a plan — and let the host compile it into a program, so an on-device model can do work that used to require a cloud call.

A new primitive

ALGAL is not a prompt framework or a DAG engine. It is a bounded, typed, content-addressed probabilistic program: a manifest as a value, a run as a verifiable receipt, and model judgment isolated behind declared cells. That makes an organism a new kind of reusable object: hashable, transportable, evolvable, and safe to execute even when you did not write it.

The shape

cells:
  - id: route
    kind: classifier            # bounded LLM call, closed label set
    output: { kind: choice, labels: [bug, feature, question] }
  - id: as-bug
    kind: fn                    # deterministic code
edges:
  - from: route.out
    to: as-bug.tag
    guard: { equals: bug }      # the structure carries the routing

What a run produces

Every run emits a content-addressed receipt: which cells committed, which skipped, what each agent cell asked and returned, and the work ledger. algal verify replays the run offline with the recorded receipts fixed — the same manifest, the same outputs, the same digest — or reports exactly where it diverges. 

$ algal run triage.algal.json --responses triage.responses.json
$ algal verify run.receipt.json triage.algal.json
{"ok":true,"outcome":"complete","digest":"sha256:…"}

Boundaries

  • A manifest carries no host code. fn cells name host-registered functions, agent cells declare prompts/views/contracts, and expr cells carry bounded algal.expr.v1 programs as data — interpreted under fuel by one shared evaluator (Rust native + WASM), never eval'd by the host.
  • An agent cell sees only its declared view of the graph — its inputs, plus ancestor cells named in view.cells. Byte-bounded, computed, never a stuffed prompt.
  • Model output is data. It re-enters the graph only after binding to a declared output contract.
  • Agents reach back into the automaton only through tools: declared registry functions, turn-bounded, every call on the receipt. Classifiers can run in shadow — the model's decision is recorded while a declared label stays authoritative.
  • Organisms embed: a sealed, content-addressed manifest becomes one cell inside a larger organism, exposing only its declared ports. A repeat cell re-runs one for bounded rounds with carried values; an each cell maps it over a delivered list — iteration and fan-out as structure, with many ports collecting the results.
  • Failure is routable: an on:"fail" edge delivers the failure record to a recovery cell, so whether a failure is survivable is declared in the graph — not discovered mid-run. Without one, the run fails closed.
  • Payloads are content-addressed: store cells pin data under a sha256: digest and ref ports carry only the token — a payload can flow through the whole graph without entering a receipt or an agent's context until a load cell resolves it.
  • Organisms are portable: pack emits a manifest's whole embedding closure as one digest-verified bundle, and a via cell resolves a missing sub-manifest through a named transport — remote resolution, local execution, the digest is the trust.
  • Effects are pure, so they memoize: run --cache-effects serves an identical request digest from the store's recorded response — first record wins, errors never memoize, and the receipt marks the reuse cached.
  • Receipts make runs replayable, not reproducible — the same organism on fresh inputs can legitimately diverge.

Case study: cheap + tool beats frontier alone

A billing-dispute organism first retrieves an account's charge ledger through a typed tool cell, then decides whether to refund, escalate, or monitor.

Live Vercel AI Gateway result on six cases, priced from aicharts.io / AI//COST:

  • Qwen 3.5 Flash + ledger tool: 6/6 correct for $0.00131
  • Claude Opus 5 without the ledger: 4/6 correct for $0.02625

Both models fail the same evidence-only cases when they cannot look up the ledger. The structure — a typed tool call feeding a bounded classifier — is what wins, not the model brand.

Use it as an agent tool

Pack an organism into a digest-verified bundle, generate an OpenAI or Anthropic tool definition, and let a larger agent call it by running algal call. 

$ algal pack ticket.algal.json --out ./tools
$ algal tool-def ticket.algal.json
$ algal call ./tools/<bundle>.bundle.json --args ticket.args.json
{ "ok": true, "outputs": { "out": "billing" }, "receiptDigest": "sha256:..." }

The agent receives a compact result plus a receipt it can verify offline.

Habitats and self-evolution

Because a manifest is a value, an organism can generate and propose new organisms, functions, and tools. A shared store and registries become a habitat: a population that evolves through foundry search and host admission. The organism cannot rewrite its own runtime; it can only propose. The host remains the admission gate.

A live steel thread already works: bun examples/habitat/promote.ts --live lets a parent organism call a model to design a child, spawn it, and the host promotes the child to a standalone bundle if it is valid and different from the safe fallback.

Civilization

Programming becomes ecology. algal civ --live runs a measured epoch: a designer organism proposes a small plan per goal, manifest.compile.v1 compiles it into a manifest, the host measures it on train and validation cases, and only winners promote — with provenance, evidence, holdout results, and a bundle digest recorded in a verifiable population snapshot. On Apple Silicon, algal civ --live --apple runs the whole epoch on-device: Apple Intelligence proposed the plans, the host compiled and promoted all four demo goals, and algal civ-verify replays it offline.

Status

Early. algal.organism.v1 covers the manifest contract, the scheduler, the effect/receipt seam, nested organisms, bounded spawning, and offline verification. Hosted habitats, multi-owner messaging, and workflow search are deliberately deferred.
