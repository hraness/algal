- Enforce expression output contracts and argument bounds in both kernels;
  preserve general JSON source values with finite schema type unions. Reject
  capability widening through repeated, batched, and spawned calls.
- Evaluate guards once in declared edge order, charge their work, and retain
  replayable failure receipts. Bound intermediate expression growth and joined
  strings before allocation, and rebuild the shared evaluator artifact.
- Parse foreign native receipts as closed records; compare all admitted receipt
  fields; retain identical failed-verification reports and unbound-effect
  evidence. The public CLI driver compares successful and rejected operations.
- Replay evaluation, migration, and applicability evidence under application
  custody. A fabricated supported derivation cannot authorize an episode, and
  a stale unstarted episode cannot revive superseded memory.
- Keep denied or blocked work from starving newer eligible intents. Retain
  admitted writer bindings through explicit reconciliation after head changes.
- Bind channel acknowledgements to dispatch identity and payload. Preserve
  observation authority across frontier advancement while invalidating old
  applicability; changes to attestation or decoder authority still reject.
- Use actual durable episode processes, compact outcome references, and exact
  creation recovery. Failed initial admission no longer consumes application
  capacity; unknown writes remain blocked through restart.
- Persist harness mutation invalidation and task scope, check probe/frontier
  consistency, and bind candidate proposals to their actual recorded requests.
  Multi-premise coverage derives from fingerprinted dependencies.
- Protect credential fallback files with ownership, mode, link and atomic-write
  checks. Preserve Unicode redaction and decode padded native vault values.
- Store bounded UTF-8 semantic chunks, repair inconsistent older index rows,

### Scope beyond the first integrated milestone

1. **Shared CAS attribution and retention.** The lifecycle plan explicitly
   permits conservative named-namespace accounting for its first implementation.
   This fallback measures retained application metadata, serializes allocation,
   and persists reservations before publication. Reservations are not implicitly
   refunded after failures or file removal. It does not assign shared CAS values,
   manifests, receipts, or effects to applications, or provide whole-store garbage
   collection. Those require a separate ownership and preservation protocol.
2. **Broader programmable policy.** Selection among retained environment-specific
   procedure alternatives and measured useful concurrency remain subsequent
   milestones. The adaptation plan explicitly specifies a serial incumbent-versus-
   candidate evaluator for the first slice. Addressed goals are part of this
   milestone; general learned retrieval/proposal policies need separate evidence.

The inventory acceptance fixture now closes the initially missing A-to-B tool
discovery, twelve-execution evaluation, and actual host-exit/reopen evidence.
It also exposed and fixed a multi-premise integration defect: draining the last
probe had narrowed the current scope to that procedure alone, making other
valid premises stale. Current coverage comes from the host's fully fingerprinted
declared dependency set. The two-premise native query is a regression test for
that distinction. The isolated milestone's test query engine remains a unit-test
double and is not the evidence for native inference correctness.

The application crash matrix now kills owned children after an exact token/PID
barrier at `prepared`, `head-published`, `dispatch-started`, and
`dispatch-settled`, plus a fifth barrier after a local write but before its
acknowledgment. A separate verification process checks the old-or-new complete
state and referenced dependencies, rejects dispatch of orphan preparations,
replays the exact operation, and confirms that started or settled effects are
not automatically repeated. Explicit reconciliation uses the fixture's exact
local completion evidence. Both runtimes pass these five cases. These tests
exercise process termination; they do not simulate power failure, damaged
storage, or every instruction inside a filesystem primitive.

### Research and assurance limitations

The repaired implementation and its regression suite support bounded claims
about the paths exercised. They are not a machine-checked proof of type safety,
noninterference, liveness, crash consistency, or equivalence for all Bun/Rust
programs. Shared canonical fixtures are valuable differential tests; common
implementation assumptions can still cause both runtimes to accept the same
incorrect result.

Receipt replay establishes conditional execution consistency. It does not
authenticate a provider, make a reported observation true, prove dependency
coverage complete, or make arbitrary external writes exactly once. These claims
depend on trusted host admission, the declared filesystem/custody model, and
explicit reconciliation of uncertain effects. The language VM does not supply
an OS sandbox.

Authored candidates and scripted decisions demonstrate adaptation mechanics.
They do not establish learning, representative holdout performance, improved
coding ability, or economic benefit. Those claims require frozen independent
tasks, uncontaminated evaluation, incumbent and ablation controls (including
structured facts without inference), actual acquisition/evaluation overhead,
and measured uncertainty. Missing token or dollar accounting remains unknown,
not zero. No paid qualification run is implied by this review.
