# Phase 06 acceptance and remaining scope

**Decision recommendation: keep Phase 06 In progress after the current gates.** All nine listed acceptance criteria have appropriate finite-model coverage and corresponding deterministic implementation evidence available in the final gate set. I found no additional universal proof obligation hidden in those criteria. However, the phase explicitly includes **dedicated generated histories**, and the existing generated application histories do not exercise Phase 06 evolution, outbox, quota and authority composition. Fresh green model/conformance/repository/parity gates cannot fill a missing generator domain. This is a bounded implementation deliverable gap, not a newly found product correctness defect.

Read-only review of the frozen working integration (`f461dd2` plus `e588f8b`). No edits, builds, tests, model runs or changes to the ledger. Root owns the completion decision and the currently running qualification commands. File/line references below are review-time locations.

The `stateful-app` suite (`verify/protocols/run.ts:13`) executes ten Bun files individually and six exact native `application_model` selectors. It checks their presence, positive execution and source/artifact stability; it does **not** contain a state-dependent generator or shrinker. Full Bun/native gates and `scripts/application-parity.ts` contribute necessary tests outside those ten/six inventories, notably proposal/investigation, native quota/capability and full restoration/admission behavior. Passing only `stateful-app` is therefore not the entire Phase 06 validation set.

## Confirmed missing scope: generated Phase 06 composition histories

The only state-dependent generated application grammar in the repository is still Phase04's `verify/traces/schema.ts:25–27`: **application-create, application-commit, application-inspect**. `StatefulGenerator.next` in `verify/traces/generate.ts:51–79` chooses head/memory/retry/fault variations. The Bun and native drivers convert every non-create application commit into **kind memory**, with no intents; the native trace admission explicitly refuses dispatch authority (`crates/algal/src/verification_trace.rs:691,957`). The independent checker `verify/traces/check.ts:349` tracks selected application history and memory, but has no outbox, captured plan/configuration, channel/message, drain, quota or authority projection. Native Hegel's state-dependent choices retain that same grammar (`verification_trace.rs:1910–1951`). `src/application-model.test.ts` and `crates/algal/tests/application_model.rs` are useful dedicated deterministic histories, not generators. I found no newer generator providing the missing domain.

Consequently, passing all-required proves all the currently registered cases passed, not that this explicit phase scope exists. The gap should not be hidden by calling fixed test files “generated histories,” by relabeling the existing memory-only generator, or by upgrading the ledger.

## Smallest bounded implementation that closes this scope

Use a separate versioned **application history extension**, reusing Phase04's owned directory/runtime driver, strict metadata/schema readers, exact seed/history binding, public-API observation, process supervision, cross-runtime archive and shrinking machinery. Avoid expanding the old history version silently. Keep the existing 64-history/24-command and output caps unless a separately reviewed reason requires a new lower/equivalent profile. Four short scenario families are sufficient; no unbounded or full Cartesian exploration is required.

**Finite fixture domain:** two application aliases; up to four operation identities per application; two memory/schema/frontier symbols; two intent identities; two dispatcher configurations; batch one/two; finite allow/deny, observer/writer and settled/blocked/uncertain choices. Retain three revision records where a genuine create→activate→forward-restore history requires a new child; “two strategy choices” must not be confused with only two revision identities. Use real bounded proposal/migration/restoration evidence builders and shared deterministic fixture bytes. Do not assert arbitrary trusted-host or evidence-verifier truth from a symbolic flag. Separate short profiles avoid requiring every kind in one four-operation history.

**Portable actions and actual endpoints:**

- Create/commit with a closed kind enum covering memory, investigate, propose, activate, migrate and restore, exact/stale head references, finite revision/memory/intents and retained evidence references. Drive Bun `ApplicationService.create/commit` (portable core is an additional adapter profile) and native `application::Service.create/commit`. Bind parent/evidence/operation references to prior successful or explicitly retained observations; no arbitrary filesystem paths or code in the history.
- Produce/verify a drain with a complete, missing or mismatched disposition map via `produceApplicationDrain` / native drain functions, then commit migration. Retained original intents must remain visibly bound to their original snapshot.
- Fresh dispatch and explicit reconciliation via `dispatchPending`/`reconcileDispatch` and native equivalents. Diagnostic host/dispatcher fixtures choose finite current policy/configuration/plan/result states; actual callbacks record occurrence identity and perform an owned local write or channel publication. Support denials and changed plan/configuration before invocation.
- Inspect/pending/read-dispatch, CAS-message/full-delivery/channel verification and retained contention verification through the existing exported services. One generated contention sequence must reuse a formerly losing operation after head advance and observe the documented invalidation.
- Restart by reopening the actual filesystem-backed services and host against the retained root. Model fixed faults at prepared/head publication and started/after-owned-effect/before-settlement points. Preserve and join any outstanding owned callback; use an explicit release/join action if exercising late completion. Finite quota-exhaustion/side-index-removal injections must be closed **owned test faults** on derived paths at a quiescent barrier, not masquerade as ordinary product APIs or inferred native fallback.

These are not all independent free choices at every step. Generate commands from observed state and declared profile prerequisites. Always include fixed reachability obligations so a seed batch cannot pass while never creating an intent, executing a dispatch, reconciling an old plan, performing a drained migration or rejecting a changed identity.

**Independent assertions after every prefix:**

1. Selected history is an exact prefix extension or unchanged; operation/request binding, revision-memory pairing, kind-specific sequence/epoch, propose/investigate restrictions and acknowledged uncertainty match the retained records.
2. Reachable committed intents alone enter dispatch; durable started evidence precedes callback entry; fresh occurrence counts never exceed one; old uncertain/blocked work cannot be silently forgotten. Reconciliation preserves original source/plan/configuration and identity after memory advance; do not interpret a callback return as proof of remote truth.
3. Fresh writer/default-host selection and host-denial boundaries hold, and a migrated intent does not acquire new authority. Channel identity/message pair, CAS message evidence and settled-history evidence are checked as different predicates.
4. Quota ledger high-water charges/identities survive errors and deletion; namespace writes require prior reservation; separate applications cannot cross the shared allocation lane; shared CAS is excluded. Inspect real bytes/ledger, not just fixture callbacks saying “reserved.”
5. Batch budget spends new attempts exactly as the algorithm specifies; denial and retained blocked rows do not prevent later eligible work within the tested scan. Drain completeness and later contention verifiability remain observable.

The independent projection must not import the production lifecycle/admission/dispatcher functions whose result it judges. Hash helpers/driver data materialization remain declared trust seams. Preserve exact error code, uncertainty and retained byte observations rather than collapsing all refusal to “false.”

**Required shrink/replay and negative controls:**

- Save seed, generator version, concrete closed history, model/pre/post observations, actual commands, native artifact identity and source/tool bindings. Replay the identical file in both actual runtimes and compare the portable projection; freeze native artifacts as the existing runner does.
- Minimize the first failing prefix, then remove irrelevant commands with dependency-aware reference repair and lower finite choices. A candidate is retained only if the same named semantic predicate still fails; invalid/unresolved histories, tool failures and cleanup failures must not be accepted as a smaller semantic counterexample.
- Prove the shrink/replay path with deliberately incorrect **test oracle/projection** variants: ignore expected head/operation reuse, omit started evidence or forget a retained old dispatch, treat CAS message as settled delivery, change old reconcile configuration, and refund a failed reservation. Each should produce an attributable portable failing prefix that replays; do not activate production mutations in the shipping runtime.
- Admission controls reject changed seed/history, changed native artifact or source binding, removed raw rows, missing required positive transition witnesses, and a missing test/driver executable. Preserve failures and owned namespaces when command or callback collection fails.

## Priority and completion decision

1. **Required now:** collect/readmit the fresh four-model and stateful-app receipts, plus the full Bun/native/crash/parity gates. Do not infer their success from this source review.
2. **Remaining Phase06 implementation:** add the bounded generated composition history extension above, validate its controls and portable replay, register its source-bound evidence, and independently review it. This is the one confirmed scope-delivery gap; it need not grow into an exhaustive implementation refinement project.
3. **Documentation maintenance after qualification:** resolve scratch-era “real conformance pending” wording in the four SCOPE files or explicitly date it as historical without rebinding old receipts. Those statements predate the existing tests and are not proof that sparse-file/concurrent quota tests are absent—they are present in both runtimes. Source-bound scope edits require fresh affected receipts.

No further TLA model expansion is required merely to satisfy the nine stated criteria at their expressly finite/sampled level. Production refinement, full numeric codecs, general filesystem enumeration resource safety and the separate Phase07/09 acceptance work must not be used to inflate Phase06's completion requirements; they remain their own open obligations.
