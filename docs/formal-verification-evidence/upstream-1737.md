# Upstream integration after checkpoint 5e334ed

The checked checkpoint `5e334ed` is published in [PR 70](https://github.com/hraness/algal/pull/70). The integrated candidate now includes the browser/native foundation and the later upstream merge at `3f81f0ab65961959cbbbf32e6fdc7f908c201483`. Earlier saved results identify their original source and remain historical evidence.

Independent source review found two additional runtime defects. A native executor error without a saved effect could become an ordinary cell failure, producing a run that replay could not reproduce. The runtime now propagates that host failure. Configuration changes detected after a callback remain uncertain, unfinished journal intents remain blocked, and suspension handles are checked before settlement. Recorded executor errors still support ordinary failure edges.

Browser raw recovery used `Array.map`, which skipped sparse positions and serialized them as null. A million sparse positions also escaped the node limit. Recovery now requires dense own positions and counts compact JSON bytes before allocating an escaped representation. It rejects negative zero because JSON serialization would change it to zero. The import conflict in `application-contract.ts` preserves the portable Store interface and the earlier typed error and digest checks.

## Later upstream merge at 7a5c126

Main advanced again through the model-router head to `7a5c126`. Merge commit `18a11b7` keeps the reviewed custody and journal checks and repairs a browser-triage replay cost that the verification changes had introduced. Commit `d686f34` registers the reviewed rational-selector proofs and rebinds the evidence inputs to the merged tree.

The first post-merge repository check did not finish. The supervising command stopped it after 900 seconds without a final summary. Before that stop, six loopback-listener tests failed because the sandbox denied local listeners, and the browser-triage 180-second capacity test timed out after 204,440 ms. The cause was per-prefix replay verification: every custody interval reread and rehashed the transfer rows of every saved prefix. The same test took 117,579 ms on the upstream implementation.

The repair changes how rows are read, not what is checked. The local-triage core now reads a transfer as an index plus separately read rows, and `parseTransfer` still rehashes every row and enforces the byte and state limits. The browser controller reuses rows only within one custody interval, at most 4,096 of them, and rehashes each row against its index digest on first read. It keeps a bounded memo of verified indexes keyed by the digest of the index shape and its evaluation; callers cannot add memo entries, and a miss falls back to strict replay. Each interval still rereads the live index, so a head change or an independent public write is detected. Two controller tests cover those cases. The capacity test then took 125,126 ms under its unchanged 180-second deadline. The 16-task edit profile took 2,651 ms against 3,066 ms upstream, with identical before, after, capture and transfer digests. A memo-only variant without row reuse took 174,823 ms and was not adopted. No deadline was widened.
