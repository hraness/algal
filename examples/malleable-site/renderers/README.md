# Renderer feasibility

This isolated Rust workspace tests the **same admitted marketing view tree** in
Dioxus web, Dioxus desktop, and Ratatui. It does not add dependencies to the ALGAL
kernel workspace. `fixtures/view.json` is generated by the actual Rust-backed
ALGAL expression in `../surface.ts`, with the default configuration and signals.
The renderers consume that result; they do not implement another view evaluator.

The bounded input supports only `stack`, `text`, and a link whose destination is
the host-fixed `/docs/`. Stable node IDs become Dioxus keys and scoped data
attributes. Text is inserted as text rather than HTML. A split layout places body
and CTA beside one another when space permits; the terminal has its own wrapping
and color treatment. Ratatui displays the link's destination without opening it.

From this directory:

```sh
bun fixtures/generate.ts --check
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
cargo run --locked --bin surface-tui -- --snapshot
cargo run --locked --bin surface-tui
```

The interactive terminal exits with `q` or Escape. `--snapshot path/to/view.json`
loads another bounded tree and produces a plain text TestBackend rendering.
Interactive rendering uses the embedded fixture. No editor, proposal generation,
activation, or network request occurs in the TUI.

The web build requires a Rust toolchain with the `wasm32-unknown-unknown` target,
Trunk 0.21.14, and wasm-bindgen 0.2.128. With the locally qualified toolchain:

```sh
NO_COLOR=true RUSTC="$(rustup which --toolchain 1.98.1 rustc)" \
  rustup run 1.98.1 trunk build --release --locked --skip-version-check
```

The explicit compiler avoids Homebrew's `cargo` selecting a different compiler
without the WASM target. Trunk 0.21.14 expects `NO_COLOR` to be a boolean, not `1`.
The pinned wasm-opt 123 runs with explicit bulk-memory support matching this
Rust compiler's emitted instructions.
Serve the generated `dist/` using any static server. The native Dioxus desktop
build on macOS is:

```sh
cargo build --locked --no-default-features --features desktop --bin surface-dioxus
./target/debug/surface-dioxus
```

Use the repository's host scheduler for heavyweight builds and browser/native
launches, as directed by `AGENTS.md`. Do not run both Dioxus `web` and `desktop`
features in the same binary. Exact dependency resolution is retained in the
workspace's own lockfile. Ratatui is pinned because its paragraph line-count API
currently requires the `unstable-rendered-line-info` feature.

These are renderer feasibility adapters, not packaged applications. The desktop
adapter uses the platform WebView; it is not a proof of platform-native widgets.
The desktop preview has no docs route handler. Browser-hosted `/docs/` resolution
belongs to the embedding site. The tree has no input widgets, so this experiment
does **not** qualify IME, draft/focus preservation across updates, assistive
technology behavior, or general form editing. Mobile, Windows, Linux desktop,
offline model inference, app signing, and distribution remain unqualified.

The browser workbench and durable host lifecycle are implemented in the parent
example, not in these adapters. This experiment informs the later renderer choice;
it does not couple ALGAL semantics to Dioxus or Ratatui.

The [recorded measurements](measurement.json) qualify five passing Rust tests,
strict Clippy, fixture freshness, the web release build, the macOS desktop build,
and the actual [terminal snapshot](tui-snapshot.txt), with unused trailing empty rows omitted. The web distribution is
362,713 bytes before compression, including a 311,048-byte WASM module. Browser
and native window interaction evidence belongs to the integration owner's
separate visual checks; compilation alone is not runtime qualification. The
native build also reports an upstream future-incompatibility warning in
`block 0.1.6`; distribution would need a fresh toolchain/dependency qualification.

The result supports keeping the semantic tree independent of a renderer. It
does not establish that Dioxus should replace the lighter existing marketing-site
renderer or that a terminal should reproduce browser pixels.
