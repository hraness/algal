# Renderer feasibility

This isolated Rust workspace tests the **same admitted marketing view tree** in a
Ratatui terminal adapter. It does not add dependencies to the ALGAL
kernel workspace. `fixtures/view.json` is generated by the actual Rust-backed
ALGAL expression in `../surface.ts`, with the default configuration and signals.
The renderer consumes that result; it does not implement another view evaluator.

The bounded input supports only `stack`, `text`, and a link whose destination is
the host-fixed `/docs/`. Text is inserted as text rather than HTML. A split layout places body
and CTA beside one another when space permits; the terminal has its own wrapping
and color treatment. Ratatui displays the link's destination without opening it.

The earlier Dioxus web and desktop adapters were removed: their dependency
trees (WebView, GTK, servo HTML parsing) dominated this workspace's lockfile
while carrying advisories the experiment could not reach a fix for. The
[recorded measurements](measurement.json) remain as the dated evidence for
those removed adapters.

From this directory:

```sh
bun fixtures/generate.ts --check
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
cargo run --locked --bin surface-tui -- --snapshot
cargo run --locked --bin surface-tui
```

The interactive terminal exits with `q` or Escape. `--snapshot path/to/view.json`
loads another bounded tree and produces a plain text TestBackend rendering.
Interactive rendering uses the embedded fixture. No editor, proposal generation,
activation, or network request occurs in the TUI.

Use the repository's host scheduler for heavyweight builds and browser/native
launches, as directed by `AGENTS.md`. Exact dependency resolution is retained in the
workspace's own lockfile. Ratatui is pinned because its paragraph line-count API
currently requires the `unstable-rendered-line-info` feature.

These are renderer feasibility adapters, not packaged applications.
Browser-hosted `/docs/` resolution
belongs to the embedding site. The tree has no input widgets, so this experiment
does **not** qualify IME, draft/focus preservation across updates, assistive
technology behavior, or general form editing. Mobile, Windows, Linux desktop,
offline model inference, app signing, and distribution remain unqualified.

The browser workbench and durable host lifecycle are implemented in the parent
example, not in these adapters. This experiment informs the later renderer choice;
it does not couple ALGAL semantics to Ratatui.

The [recorded measurements](measurement.json) date from when the workspace also
carried Dioxus web and desktop adapters; they qualify the then-present web
release build, the macOS desktop build, five passing Rust tests,
strict Clippy, fixture freshness,
and the actual [terminal snapshot](tui-snapshot.txt), with unused trailing empty rows omitted. The web distribution was
362,713 bytes before compression, including a 311,048-byte WASM module. Browser
and native window interaction evidence belongs to the integration owner's
separate visual checks; compilation alone is not runtime qualification.

The result supports keeping the semantic tree independent of a renderer.
It does not establish that a terminal should reproduce browser pixels.
