# Finite dynamic-spawn scheduler slice

Phase 07 remains in progress. Seventeen fixed fixtures extend a copied independent scheduler oracle with a closed catalog of at most two normalized single-agent dynamic manifests. The oracle imports only Node crypto. Production normalization and execution live in a separate adapter/worker. Unknown dynamic manifests and nonempty spawn args are unsupported fixture inputs, never inferred product errors.

The primary witness is five activations, two calls, 1550 work units: two distinct spawn paths retain A/B under the same request digest. Other cases cover shared root step/call/depth/work limits, retained retry costs, root/cell byte clamping, child budget noninterference and selection between two wire definitions. Eight executable oracle mutants exercise counters, deduplication, repeated first output, path reuse, child budget substitution, digest forging, retry refunds and widened bytes. The baseline explicitly uses no cache.

Each new receipt must match the independent projection and replay in both runtimes. Two parser-valid, redigested same-digest effect mutations (reordered and duplicated first output) retain original cell outputs and must fail real replay in both runtimes. These are replay mutation controls, distinct from oracle transition mutants. The worker checks production normalization against the independently prescribed dynamic wire before execution. Both runtimes use fresh separate stores; native run explicitly enables persistence with --write and admits only the exact receipt-CAS diagnostic. Its saved root manifest and full receipt bytes are checked alongside the dynamic manifests; replay uses an empty MemoryStore/verification directory. Actual dynamic CAS bytes are compared to prescribed wire, including depth refusal after dynamic admission. The byte check rejects equivalent parsed JSON with reordered keys, duplicate keys or extra whitespace. Replay reports use a closed shape; successful reports must name the exact receipt digest and outcome. Native request identity is checked through expected digests/effect order; Bun additionally retains actual request objects.

Commands are supervised with 30s/256KiB caps. Static workers admit only the 17 named fixtures and three closed modes. JSON retention preflights exact encoded byte size before serialization. Parent command headroom is reserved before execution, worker metadata has 2MiB/eight-file caps, and archive inventory is streamed with 16MiB/512-file/1024-entry/depth-8 bounds and regular-file checks. Production store writes are from fixed small fixtures and remain a trusted runtime boundary; this harness does not prove arbitrary product I/O allocation bounds. The owned checkout/scratch tree is assumed cooperating, not hostile concurrent mutation.

Bindings include all captureBinding governed/property inputs, exact scratch source files, Bun bytes through captureBinding.runtime, frozen native bytes, and the pinned native build manifest/source list. Initial execution evidence retains raw argv/stdout/stderr/custody/results and a hashed file inventory. Each command rereads the declared immutable file inputs after exit and records before/after hashes; original fixture files are reread at case close. These checks detect retained changes in a cooperating fixture tree, not an adversary that changes and restores a file between observations. The closed offline reader reconstructs exactly this finite inventory under caller-pinned source and artifact authority. It does not authenticate externally fabricated command records.

General dynamic parsing, nonempty args, capabilities, nested spawn, repeat/each around spawn, suspension/resume, journal poison, tools/turns, recall, cache, arbitrary DAGs, broad structural/receipt amplification and arbitrary providers remain outside this finite inventory. The existing 206 scheduler comparisons are not rerun or claimed by this candidate.
