# Scope and bounds

The domain is a finite staged create/investigate/memory/outbox history over two application aliases, four operation slots per application, two memories/configurations and one or two intents. It covers denied dispatch, blocked/unknown/settled callbacks, retained old-source work, configuration/plan changes, stale heads, exact/conflicting operation retries, prepared failures and uncertain acknowledgment after head publication. Each profile requires explicit positive witnesses, so a seed cannot pass by omitting the relevant states.

Every trace is checked against the independent per-prefix oracle. Shared observations and local effect files must agree exactly across runtimes and fresh-root repeats. Raw error code/message/uncertainty/details/wake are retained. Exactly two declared runtime differences remain: native uncertain acknowledgment embeds the operation in its message where Bun uses details; reconciliation before admission uses native PARSE_FAILED versus Bun INTERNAL. Additional drift fails.

The scope is object reopening in the same worker plus complete replays on fresh roots. It is not same-root process-crash recovery. Fixture callback files establish these local effects only, not truth or exactly-once behavior of arbitrary callbacks and remote providers. Fixture policy decisions, canonical hashing, filesystem/OS behavior, Bun/native runtime/compiler behavior and source/build provenance remain assumptions.

Bounds are four histories, 24 commands per history, 32 callbacks, 32 KiB history input, 1 MiB packet, 64 KiB raw dispatch and 4 KiB local effect. Each target command has a 120-second deadline and 256 KiB captured-output ceiling. Five shrink controls allow at most 32 candidates plus initial/final reproductions, so the complete matrix has at most 186 worker commands. Only independent domain rejection is skipped; custody, timeout, IO, parser or baseline semantic failures abort shrinking. Baseline admission is wrapped before the explicit projection mutation, so only a post-mutation semantic mismatch may count as an expected counterexample. The semantic property and full mismatch signature must survive every accepted shrink and the final repeat.

The retained archive has a 48 MiB cumulative byte limit, 8 MiB cumulative command-output limit, 1.25 MiB record limit and a reserved 16 KiB terminal failure record. Capacity is checked before launching a worker or serializing a record. Complete successful physical inventory includes at most 2,048 files/directories and depth three below the archive root; extra/missing/nonregular entries reject. Temporary owned application roots are removed only after parent admission; failed roots remain diagnostic evidence and cannot count as a successful archive. Directory API prefetch, parsed JSON allocation, compiler/OS caches and production internals are not a whole-process allocation or RSS bound. No whole-suite wall-clock theorem is claimed.

The reader validates selected and recorded argv as one to 64 nonempty NUL-free strings, each at most 4,096 characters and UTF-8 bytes; authorized absolute paths have the same byte bound. It reconstructs all argv from caller authority and ordinal paths, validates exact input/output bytes and command status/custody, reruns the generator and oracle, and repeats the deterministic shrink algorithm against retained attempts. It rebuilds accounting and hashes rather than trusting result counts. Historical consistency and current-source applicability have distinct labels. Readmission assumes cooperating owned files; it is not isolation from a hostile same-user filesystem race. The registered result contains a small admission and raw manifest, while the raw files must be retained separately or as bounded chunks before delivery.

Proposal/activation/restoration, migration/drain, quota, channel/message, contention compositions and broader generated domains remain open Phase06 work. This reference makes no TLA+, Lean, production-refinement or universal correctness claim.
