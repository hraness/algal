# Phase 08 expression boundary corpus pilot

The corpus suite registers this finite expression pilot. It claims no source proof, new runtime package dependency, native build, or Phase 08 completion.

The first engine generates a finite pure expression grammar and raw byte envelope controls. The independent oracle uses exact BigInt addition/subtraction/negation and direct Boolean denotations, with explicit short circuit and a deliberate division-by-zero terminal. It does not import production evaluation, canonicalization, schema, or fuel logic. Its strings are valid scalar text; UTF-16 length is computed from scalar widths. All generated arithmetic stays in a reviewed exact binary64 integer subset. The oracle checks value/error class; it does not independently certify fuel. Full output/fuel target agreement is a separate sampled comparison.

Raw inputs remain bytes through native and WASM byte entry points. Malformed UTF-8, surrogate escapes, duplicate envelope keys, and numeric spellings have reviewed expected projections. Bun public-wrapper comparison applies only to grammar cases, because JSON.parse/serialization would erase raw distinctions. Bun uses the same committed WASM evaluator as one raw target; it is wrapper correspondence, not an independent evaluator.

The harness reuses the repository's runCommand supervisor and artifact identity reader. Each worker handles one case under a finite deadline/output limit. Artifacts must be explicitly supplied and are bound before/after execution. No ambient native artifact discovery, compilation, or fallback. A local profile can qualify the Bun wrapper and committed WASM only, clearly distinct from the full profile requiring frozen native and rebuilt WASM artifacts with separate build provenance.

The shrinker accepts only the same named semantic mismatch; parse errors, process faults, timeouts, and unrelated differences cannot become a successful reduction. It is deterministic, bounded, and reconfirms the final candidate. Grammar shrinking preserves the independently admitted subset. Raw shrinking is restricted to inputs whose expected outcome remains independently known (the current malformed-UTF8 family), rather than blessing arbitrary production output as an oracle.

The search charges at most 32 generation steps, including rejected candidates and intermediate grammar visits/copies. It stops scheduling new reductions after 60 seconds of search; this is not a 60-second total wall-clock guarantee. Original and final replay are separate, and one search replay can cross that scheduling boundary. A replay has 1/2/3 sequential supervised commands for local/native/full profiles, each 10-second execution deadline plus the existing 2-second cleanup bound. Thus nominal timeout-accounting envelopes are 96/132/168 seconds for search+original+final, excluding bounded local computation/IO and scheduling delay. OS progress and cooperative process custody remain assumptions; the registered adapter has finite case/command counts and per-command deadlines, without claiming a tighter whole-suite wall-clock bound.

Aggregate command capture is capped at 16 MiB, with the remaining allowance passed to runCommand before each launch. The archive is capped at 32 MiB and 2,048 files; owned metadata receives an exact JSON UTF-8 size preflight and reserves bytes before serialization and IO. Each command checks capacity for an 8 MiB worst-case encoded record and three failure-evidence files before launch. One file and 64 KiB stay reserved for terminal failure metadata. Successful per-case output lives in separate bound records; the summary retains references, not another unbounded concatenation. Failure finalization omits accumulated rows and preserves the original exception if evidence retention itself fails. These are application capture/retention limits, not a measured RSS or kernel-buffer bound.

Out of scope: full operator/cell/schema grammar, raw SDK prototypes/accessors/holes, generic float rounding oracle, graph/scheduler/capabilities, production receipt/evidence mutation, aggregate resource closure, physical directory allocation, archive/adapter frames, Linux qualification, universal correctness. The repository formal-verification plan retains the broader evidence-mutation and coverage obligations as incomplete.
